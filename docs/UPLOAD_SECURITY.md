# سياسة ومعايير أمان تدقيق واستقبال الملفات (Upload Security & Document Ingestion Policy)

---

## 1. نظرة عامة (Overview)

تعتمد المنظومة الأكاديمية خط دفاع وقائي مركزي موحد لكافة بوابات استقبال وتدقيق الملفات الأكاديمية (`Upload Validation Service`). تهدف هذه السياسة إلى حماية الخادم والبيئة التشغيلية المحلية من الملفات المعطوبة، والهجمات الانضغاطية، والتخطي المساري، والملفات فائقة الحجم، مع الحفاظ الكامل على سير العمل الأكاديمي أوفلاين بنسبة 100%.

---

## 2. الصيغ الأكاديمية المدعومة (Accepted Formats)

| الصيغة | الامتداد | التوقيع الرقمي (Magic Bytes) | المعايير الهيكلية الإلزامية |
| :--- | :--- | :--- | :--- |
| **وثائق PDF** | `.pdf` | `%PDF-` | بنية صفحات صالحة، غير مشفرة، لا تتجاوز الحد الأقصى للصفحات |
| **مستندات Word** | `.docx` | `PK\x03\x04` | حزمة OpenXML تحوي `[Content_Types].xml` و `word/document.xml` |
| **النصوص المجردة** | `.txt` | نصوص عادية | ترميز مقروء (UTF-8, Windows-1256)، خلو تام من بايتات NUL الثنائية |

> [!IMPORTANT]
> - الصيغة القديمة الثنائية `.doc` غير مدعومة افتراضياً نظراً لمخاطر الماكرو القديمة وعدم أمان معالجتها محلياً بدون محولات معزولة.
> - يتم فحص التوقيع الرقمي للمحتوى الفعلي، ولا يُعتمد على ترويسة `Content-Type` القادمة من المتصفح لكونها استشارية فقط.

## 3. الحدود المؤسسية والقصوى للأحجام والموارد (Resource Limits)

| المتغير | القيمة الافتراضية | التوصيف المؤسسي |
| :--- | :--- | :--- |
| `MAX_UPLOAD_BYTES` | **50 MB** | الحد الأقصى لحجم البحث الفردي |
| `MAX_BATCH_TOTAL_BYTES` | **150 MB** | الحد الأقصى لإجمالي حجم الدفعة المستقلة |
| `MAX_THESIS_TOTAL_BYTES` | **100 MB** | الحد الأقصى لإجمالي ملفات الرسالة الواحدة |
| `MAX_REFERENCE_UPLOAD_BYTES` | **50 MB** | الحد الأقصى لملف البحث المرجعي المستورد |
| `MAX_FILES_PER_BATCH` | **30 ملفاً** | الحد الأقصى لعدد الأبحاث داخل الدفعة الواحدة |
| `MAX_FILES_PER_THESIS` | **20 ملفاً** | الحد الأقصى لعدد ملفات/أبواب الرسالة الواحدة |
| `MAX_PDF_PAGES` | **1,000 صفحة** | الحد الأقصى لعدد صفحات ملف PDF الواحد |
| `MAX_DOCX_ENTRIES` | **1,000 عنصر** | الحد الأقصى لعدد الملفات داخل أرشيف DOCX |

| `MAX_TXT_BYTES` | **20 MB** | سقف حجم الملفات النصية المباشرة |

## 4. دورة حياة التخزين والعزل المرحلي (Staging Storage Lifecycle)

تخضع كافة الملفات المرفوعة لدورة حياة ذرية محكمة تضمن عدم وصول أي بايتات غير مدققة إلى التخزين النهائي:

```
[دفق البايتات المرفوعة]
          │
          ▼
[1. العزل في مجلد Staging المؤقت (.staging_uploads)]
   ├── فحص الحجم اللحظي أثناء الدفق (Streaming Size Check)
   └── حساب البصمة الرقمية (SHA-256 Digest)
          │
          ▼
[2. الفحص الهيكلي والتوقيع الرقمي (Signature & Structure)]
   ├── فحص Magic Bytes وبنية الأرشيف/المستند
   ├── فحص التشفير وحدود الموارد والصفحات
   └── منع هجمات Zip-Slip و Path Traversal
          │
          ├── [فشل التحقق] ──► حذف فوري لملف Staging + إرجاع كود خطأ قياسي
          ▼ [نجاح التحقق]
[3. النقل الذري (Atomic Promotion via os.replace)]
          │
          ▼
[4. مجلد التخزين المعتمد (Finalized Storage) + ربط سجل DB]
```

## 5. سياسة تنقية أسماء الملفات (Filename Sanitization Policy)

- يتم التعامل مع اسم الملف الأصلي كبيانات وصفية للعرض فقط (`Display Metadata`).
- تنقية الاسم من مسارات التخطي (`..`)، والمسارات المطلقة لنظام التشغيل (`C:\` أو `/etc/`)، ومسارات UNC (`\\server\share`).
- إزالة محارف التحكم وبايتات NUL.
- معالجة الأسماء المحجوزة في نظام Windows مثل (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`).
- الحفاظ الكامل وغير المشوه على أسماء الأبحاث المكتوبة باللغة العربية والرموز الأكاديمية المشروعة.

---

## 6. سياسة الوثائق المشفرة (Encrypted Documents Policy)

- ترفض المنظومة استلام أو فحص أي وثيقة PDF أو ملف Word محمي بكلمة مرور أو مشفر برمجياً.
- لا تقوم المنظومة بأي محاولات لكسر كلمات المرور، ويُعاد كود الخطأ المستقر `FILE_ENCRYPTED` مع توجيه المستخدم لرفع نسخة غير محمية.

## 7. أكواد الأخطاء القياسية لتدقيق المدخلات (Upload Error Codes)

| كود الخطأ | السبب |
| :--- | :--- |
| `FILE_UNSUPPORTED` | امتداد الملف غير موجود في القائمة المسموحة (`.pdf`, `.docx`, `.txt`). |
| `FILE_TOO_LARGE` | حجم الملف يتجاوز السقف المحدد للملف الفردي. |
| `FILE_EMPTY` | الملف المرفوع فارغ (0 بايت). |
| `FILE_SIGNATURE_MISMATCH` | المحتوى الفعلي لا يطابق التوقيع الرقمي للامتداد (مثال: exe أعيدت تسميته pdf). |
| `FILE_ENCRYPTED` | الملف محمي بكلمة مرور أو مشفر. |
| `FILE_CORRUPTED` | بنية الملف معطوبة أو غير قابلة للقراءة بأمان. |
| `PDF_PAGE_LIMIT` | عدد صفحات ملف PDF يتجاوز 1000 صفحة. |
| `DOCX_ARCHIVE_UNSAFE` | حزمة Word تحوي مسارات تخطي غير آمنة (Zip-Slip). |
| `DOCX_RESOURCE_LIMIT` | حزمة Word تتجاوز سقف فك الضغط أو نسبة الضغط المسموحة (Zip-Bomb). |
| `BATCH_LIMIT_EXCEEDED` | تجاوز عدد الملفات أو الحجم الإجمالي المسموح للدفعة أو الرسالة. |

## 8. حدود الحماية وإخلاء المسؤولية الأمنية (Malware & Security Boundary)

> [!CAUTION]
> - **طبيعة التحصين:** يوفر هذا النظام تدقيقاً بنيوياً وهيكلياً صارماً للمستندات وحماية متقدمة ضد هجمات استنزاف الموارد ومخاطر المعالجات البرمجية (Parsers).
> - **حدود مكافحة الفيروسات:** التدقيق الهيكلي **لا يُعد بديلاً عن برامج مكافحة الفيروسات المؤسسية (Antivirus Endpoint Protection)**. المنظومة مصممة لتعمل محلياً وأوفلاين بالكامل دون الاتصال بأي خدمات فحص سحابية، وتوفر نقطة تكامل محلية آمنة في حال رغبت المؤسسة في ربط ماسح فيروسات محلي على مستوى نظام التشغيل.
