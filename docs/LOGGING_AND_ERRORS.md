# دليل التسجيل الهيكلي ومعالجة الأخطاء الآمنة (Structured Logging & Safe Error Handling)

## 1. نظرة عامة (Overview)

تم بناء وتطوير طبقة **التسجيل الهيكلي ومعالجة الأخطاء الآمنة (Phase 12 — Structured Logging & Safe Error Handling)** لتوفير رؤية تشخيصية فنية دقيقة للمسؤولين التقنيين في كلية الدراسات العليا دون المساس بسرية وخصوصية الأبحاث العلمية ودون تسريب أي بيانات اعتماد أو مسارات نظام تشغيل للمستخدمين العاديين، مع العمل 100% أوفلاين محلياً.

---

## 2. الفصل بين سجل التدقيق المؤسسي والسجلات التشغيلية (Audit Trail vs. Operational Logs)

تعتمد المنظومة فصلاً معمارياً صارماً بين نظامين مستقلين:

| المعيار | سجل التدقيق المؤسسي (Audit Trail) | السجلات التشغيلية الفنية (Operational Logs) |
| :--- | :--- | :--- |
| **السؤال الأساسي** | **من قام بهذا الإجراء الأمني/المؤسسي ومتى؟** | **ماذا حدث تقنياً داخل محركات ومكونات الخادم؟** |
| **مكان الحفظ** | قاعدة بيانات SQLite المؤسسية (`AuditLog`). | ملفات نصية مهيكلة محلية (`logs/application.log`). |
| **الأمثلة** | تسجيل دخول، تغيير كلمة مرور، اعتماد تقرير، تعديل دور. | استثناء في استخراج PDF، فشل فحص SHA-256، تدوير ملفات. |
| **التأثير** | لا يتأثر بالأخطاء البرمجية العادية أو طلبات 404. | يسجل كافة الأحداث التقنية مع تتبع المكدس محلياً. |

---

## 3. معمارية التسجيل وتدوير الملفات (Log Locations & Rotation)

- **المسار:** `logs/application.log` (محلياً ضمن مجلد التطبيق).
- **آلية التدوير:** `RotatingFileHandler`.
- **الحد الأقصى لحجم الملف:** 10 ميجابايت (`10 MB`).
- **عدد ملفات التدوير المحتفظ بها:** 5 ملفات احتياطية (`backupCount=5`).
- **الترميز:** `UTF-8` كامل لضمان سلامة النصوص والرسائل باللغة العربية.

### مستويات التسجيل المعتمدة (Log Levels):
- `DEBUG`: تشخيصات بيئة التطوير فقط.
- `INFO`: أحداث دورة الحياة التشغيلية الرئيسية (بدء الفحص، اكتمال المعالجة).
- `WARNING`: حالات استثنائية قابلة للتعافي (مساحة قرص منخفضة، تأخر نسخة).
- `ERROR`: فشل تقني في تنفيذ عملية (تعذر استخراج ملف، خطأ قاعدة بيانات).
- `CRITICAL`: تعطل كلي في مكون رئيسي يمنع استمرار عمل المنظومة.

## 4. معرف تتبع الطلب الموحد (Request Correlation ID)

يتم توليد معرف UUID فريد (`X-Request-Id`) لكل طلب HTTP وارد:
- متاح تلقائياً عبر سياق Flask في `g.request_id`.
- يُحقن في ترويسة الاستجابة الصادرة للمتصفح `X-Request-Id`.
- يُضمن في كافة السجلات التشغيلية لتسهيل ربط أثر العمليات.
- يظهر للمستخدم في مغلف الخطأ ليتمكن من تزويد الدعم الفني برقم التتبع دون تسريب تفاصيل الخطأ.

## 5. دليل أكواد الأخطاء القياسية (Error Code Catalog)

| كود الخطأ (Error Code) | حالة HTTP | المعنى ودلالة الخطأ |
| :--- | :---: | :--- |
| `AUTH_REQUIRED` | 401 | يلزم تسجيل الدخول أولاً للوصول للخدمة. |
| `AUTH_FORBIDDEN` | 403 | المستخدم لا يمتلك الصلاحية المؤسسية المطلوبة. |
| `AUTH_INVALID_CREDENTIALS` | 401 | اسم المستخدم أو كلمة المرور غير مطابقة. |
| `VALIDATION_ERROR` | 400 | المدخلات غير صالحة أو المعاملات ناقصة. |
| `NOT_FOUND` | 404 | العنصر أو الرابط المطلوب غير موجود. |
| `METHOD_NOT_ALLOWED` | 405 | طريقة الطلب غير مسموح بها لهذا المسار. |
| `PAYLOAD_TOO_LARGE` | 413 | حجم الملف المرفوع يتجاوز الحد الأقصى المسموح. |
| `FILE_EXTRACTION_FAILED` | 400 | تعذر استخراج النص من ملف البحث. |
| `FILE_UNSUPPORTED_TYPE` | 400 | نوع الملف غير مدعوم (يقبل PDF و DOCX و TXT). |
| `FILE_CORRUPTED` | 400 | الملف تالف أو مصمت أو غير قابل للقراءة. |
| `OCR_FAILED` | 400/500 | تعذر إجراء التعرف الضوئي على المستند الممسوح. |
| `OCR_UNAVAILABLE` | 503 | محرك Tesseract المحلي غير مثبت أو حزمة العربية ناقصة. |
| `SCAN_FAILED` | 500 | تعذر إتمام مهمة الفحص المقارن في الخلفية. |
| `DATABASE_ERROR` | 500 | حدث خطأ أثناء تنفيذ عملية في قاعدة البيانات. |
| `STORAGE_ERROR` | 500 | تعذر الوصول إلى مساحة التخزين أو نفاد المساحة. |
| `BACKUP_FAILED` | 500 | فشل إنشاء أو فحص سلامة النسخة الاحتياطية. |
| `RESTORE_FAILED` | 500 | فشلت عملية استعادة النسخة الاحتياطية. |
| `FILE_INTEGRITY_FAILED` | 400 | عدم تطابق بصمة SHA-256 للملف الرقمي. |
| `INTERNAL_ERROR` | 500 | خطأ داخلي غير متوقع في الخادم. |

## 6. مغلف استجابة الخطأ الموحد (API Error Envelope)

تعتمد كافة مسارات الـ API صيغة موحدة آمنة للأخطاء:

```json
{
  "success": false,
  "error": {
    "code": "FILE_EXTRACTION_FAILED",
    "message": "تعذر استخراج النص من الملف المرفوع نظراً لكونه مصمتاً أو تالفاً.",
    "request_id": "a9d7c3e5f2b14e67"
  },
  "message": "تعذر استخراج النص من الملف المرفوع نظراً لكونه مصمتاً أو تالفاً.",
  "request_id": "a9d7c3e5f2b14e67"
}
```

## 7. سياسة حجب البيانات والخصوصية التامة (Privacy & Redaction Policy)

1. **حجب البيانات السرية والتوكنات:**
   - الحجب التلقائي لكلمات المرور وتجزئاتها (`password`, `password_hash`).
   - حجب التوكنات والـ JWT والـ Cookies وترويسات التفويض `Authorization`.
2. **حظر نصوص الأبحاث في السجلات:**
   - يمنع منعاً باتاً تسجيل نصوص الأبحاث الكاملة أو الأدلة والاقتباسات أو متجهات التضمين في السجلات الفنية.
3. **عزل مسارات نظام التشغيل:**
   - استبدال المسارات المطلقة مثل `C:\Users\...` بمسارات رمزية آمنة في واجهات المستخدم والردود البرمجية.
4. **الحماية ضد حقن السجلات (CRLF Injection):**
   - تنقية كافة المدخلات من محارف النزول لسطر جديد `\r` و `\n` ومحارف التحكم لمنع تزوير سجلات إضافية.
