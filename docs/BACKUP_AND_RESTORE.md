# دليل النسخ الاحتياطي والاسترداد المعاملاتي (Backup, Restore & Disaster Recovery Runbook)
## منظومة كاشف السرقات العلمية الأكاديمي للنصوص العربية — الإصدار v1.4.0-rc

## 1. نطاق وتصنيف البيانات (Data Scope & Classification)

لضمان الاتساق المنطقي وسرعة الاستعادة، تُصنف بيانات المنظومة بدقة إلى ثلاثة مستويات:

```
+-----------------------------------------------------------------------------------+
| [1] البيانات الأصلية الإلزامية (Authoritative Data - النسخ الاحتياطي الإلزامي)     |
|   - قاعدة البيانات الرئيسية (Metadata, Research, Reports, Audit Logs, Users)     |
|   - مخزن الوثائق المرجعية والأبحاث المتصل بالمحتوى (Authoritative CAS Documents)   |
|   - حوكمة الإصدارات المرجعية وسجلات التغيير (Corpus Governance Metadata)          |
|   - لقطات التقارير المعتمدة غير القابلة للتعديل (Finalized Report Snapshots)       |
|   - ملفات التكوين والبيانات الوصفية للإصدار (Configuration & Release Manifests)   |
+-----------------------------------------------------------------------------------+
                                         |
+-----------------------------------------------------------------------------------+
| [2] البيانات المشتقة القابلة لإعادة البناء (Derived Rebuildable Data)              |
|   - فهارس الاسترجاع الثنائية المقلوبة (Two-Stage Inverted Retrieval Postings)     |
|   - لا تُضمن إجبارياً في النسخ الضخمة لتوفير الحجم؛ يُعاد توليدها آلياً عبر:      |
|     `python tools/rebuild_retrieval_index.py`                                     |
+-----------------------------------------------------------------------------------+
                                         |
+-----------------------------------------------------------------------------------+
| [3] البيانات المؤقتة والعابرة (Temporary / Ephemeral Data - تُستثنى من النسخ)     |
|   - مساحات التجهيز المؤقتة لرفع الملفات (Staging Directories)                     |
|   - سجلات العمليات العابرة وقوائم القفل المؤقتة (Temporary Cache / Lock States)   |
+-----------------------------------------------------------------------------------+
```

## 2. أنواع النسخ الاحتياطي وآلية القفل (Backup Types & Concurrency Locking)

1. **النسخ الكامل (Full Authoritative Backup):**
   - نسخ لقطة متسقة من قاعدة البيانات بالتزامن مع كائنات التخزين المرجعية `CAS Documents`.
   - توليد بيان وصفي موحد للنسخة الاحتياطية (`backup_manifest.json`) يحتوي على بصمات `SHA-256` الفردية والإجمالية.
2. **نسخ التكوين (Configuration Backup):**
   - نسخ الإعدادات ومفاتيح التكوين والإصدارات فقط.
3. **القفل الموزع لمنع التضارب (Distributed Backup Lock):**
   - استخدام قفل رسمي حصري `BACKUP_OPERATION_EXCLUSIVE` عبر جدول `distributed_locks`.
   - منع عمليتين متزامنتين من إنشاء نسخ احتياطية متضاربة، مع تحرير تلقائي للقفل بعد اكتمال العملية أو عند انتهاء صلاحية الإيجار في حال انهيار العملية الحائزة.

## 4. تدريب الاستعادة والتعافي الحقيقي (Validated Restore Drill Procedure)

خطوات الاستعادة الميدانية المعتمدة والمختبرة برمجياً:

1. **التحضير والتأكد من البيئة:** إيقاف خوادم التطبيق وعمال الطابور النشطين.
2. **التحقق من سلامة النسخة الاحتياطية قبل الاستعادة:**
   - فحص بصمات `SHA-256` لملف قاعدة البيانات وكافة ملفات CAS مقارنة بـ `backup_manifest.json`.
   - في حال وجود أي تباين في البصمات: **إيقاف الاستعادة فوراً ورفض استخدام النسخة التالفة (Fail-Closed)**.
3. **استعادة الملفات الأصلية:**
   - استعادة ملف قاعدة البيانات إلى المسار الرسمي.
   - استعادة مجلد الوثائق `storage/documents/` مع التحقق من الهيكل الثنائي.
4. **التحقق الهيكلي من قاعدة البيانات:**
   - تشغيل `PRAGMA integrity_check;` للتأكد من سلامة الجداول والفهارس.
5. **إعادة بناء البيانات المشتقة:**
   - إعادة بناء فهرس الاسترجاع المرجعي آلياً من الوثائق المستعادة عبر أمر الإدارة:
     `python tools/rebuild_retrieval_index.py --force`
6. **فحص ما بعد الاستعادة (Post-Restore Verification):**
   - التحقق من إمكانية تسجيل الدخول، مطابقة أعداد الأبحاث والتقارير، وإجراء فحص استدلالي اختباري للتأكد من الجاهزية التشغيلية الكاملة.
