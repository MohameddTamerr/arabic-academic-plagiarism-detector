# وثيقة حدود التوسع وجاهزية قاعدة البيانات المؤسسية (Database Architecture & Scaling Limits Guide)
**منظومة كشف الاستلال الأكاديمي والتحكيم الداخلي (Arabic Academic Integrity & Review System)**

---

## 1. الإطار المعماري الحالي وبيئة التشغيل (Current Architecture & Envelope)
تعتمد المنظومة حالياً على **محرك SQLite مع نمط سجل المعاملات المتزامن (WAL Mode)** كقاعدة بيانات إنتاجية محلية رسمية ومحصنة، صُممت خصيصاً للتشغيل المحلي في الخوادم المؤسسية الداخلية المستقلة (100% Offline Single-Server Deployment).

### الافتراضات التشغيلية المدعومة حالياً:
- **نطاق النشر:** خادم محلي مفرد (Single On-Premises Server) أو جهاز مؤسسي مخصص.
- **سعة التزامن المدعومة:**
  - قراءات متزامنة غير محدودة (Concurrent Multi-Readers) بفضل نمط WAL.
  - كاتب متسلسل مفرد (Single Sequential Writer) محمي بمهلة انتظار `busy_timeout = 10000ms`.
  - سعة معالجة تصل إلى **4–8 عمليات فحص أكاديمي متزامنة** عبر `ThreadPoolExecutor` و `MAX_CONCURRENT_SCANS`.
  - معالجة دفعات تصل إلى مئات الأبحاث أوفلاين دون التأثير على استجابة واجهة المستخدم.

## 2. التهيئة القياسية لـ PRAGMA والمسوغات الهندسية (Standard PRAGMA Configuration)

تُنفذ الإعدادات مركزياً عبر اتصال المحرك في [`app/repositories/base_repo.py`](file:///c:/Users/user/Downloads/Baba/app/repositories/base_repo.py):

| أمر الـ PRAGMA | القيمة المعتمدة | المسوغ الهندسي والأكاديمي |
|---|---|---|
| `PRAGMA foreign_keys` | `ON` | تفعيل التحقق الصارم من المفاتيح الأجنبية لمنع الأيتام في الجداول وضمان سلامة العلاقات. |
| `PRAGMA journal_mode` | `WAL` | تفعيل Write-Ahead Logging لتمكين القراءات المتزامنة دون حظر الكاتب، وتسريع الكتابة المتسلسلة. |
| `PRAGMA synchronous` | `NORMAL` | في نمط WAL، يوفر الوضع `NORMAL` أماناً كاملاً ضد انهيار التطبيق مع تنفيذ الـ fsync الحقيقي عند نقاط التفتيش فقط. |
| `PRAGMA busy_timeout` | `10000` | مهلة 10 ثوانٍ لانتظار تحرير الأقفال عند التزاحم لمنع ظهور خطأ `database is locked` المفاجئ. |
| `PRAGMA temp_store` | `MEMORY` | حفظ الجداول والفهارس المؤقتة وترتيب الاستعلامات في الذاكرة العشوائية لتقليل استهلاك القرص. |
| `PRAGMA wal_autocheckpoint` | `1000` | تنفيذ نقطة تفتيش تلقائية كل 1000 صفحة (~4MB) للحفاظ على صغر حجم ملف الـ WAL. |

## 3. سياسة قصر المعاملات (Short Write Transaction Policy)
تلتزم المنظومة بسياسة صارمة تفصل بين الحسابات الثقيلة ومعاملات قاعدة البيانات:
- **القاعدة الذهبية:** العمليات الحسابية الكثيفة (استخراج النصوص، فك صفحات PDF، محرك OCR، مطابقة المتواليات، حساب Jaccard/TF-IDF، التضمين الدلالي، حساب SHA-256) **تنفذ بالكامل في الذاكرة خارج أي معاملة كتابة لقاعدة البيانات**.
- **نمط الحفظ:**
  $$\text{Compute in Memory} \longrightarrow \text{Open Short Session} \longrightarrow \text{Commit} \longrightarrow \text{Close}$$
- يضمن هذا النمط ألا تتجاوز معاملات الكتابة بضعة أجزاء من الألف من الثانية (Milliseconds)، مما يمنع حدوث اختناقات الأقفال.

## 4. مؤشرات الأداء وعلامات التحذير (Workload Migration Indicators)
يجب مراعاة الترقية والانتقال إلى محرك خادم مركزي مثل **PostgreSQL** عند ظهور أي من المؤشرات التالية:
1. **تكرار تزاحم الأقفال:** تكرار تسجيل أخطاء `database is locked` في السجلات بالرغم من مهلة 10 ثوانٍ.
2. **توسع النشر الأفقي (Multi-Node / Multi-Server):** الحاجة لتشغيل المنظومة على عدة خوادم ويب موزعة تتصل بقاعدة بيانات مركزية واحدة عبر الشبكة (حيث لا تدعم SQLite المشاركة عبر NFS/SMB بأمان).
3. **ارتفاع معدل التزامن المتزامن العالي:** الحاجة لمعالجة أكثر من 50 كتابة متزامنة حقيقية في نفس الثانية على مستوى الوزارة.
4. **تضخم ملف WAL المستمر:** نمو ملف الـ WAL ليتجاوز 100 ميجابايت بشكل مستمر مع بطء نقاط التفتيش.

## 5. خطة الانتقال المستقبلية إلى PostgreSQL (Future Migration Path)
تمت هيكلة طبقة البيانات في المنظومة لتسهيل الانتقال المستقبلي دون تعديل خوارزميات الفحص أو منطق الأعمال:
1. **استخدام SQLAlchemy Core & ORM:** كافة الاستعلامات مكتوبة بنمط SQLAlchemy القياسي الجاهز لـ PostgreSQL.
2. **عزل خصائص SQLite:** حصر أوامر الـ PRAGMA والنسخ الاحتياطي الخاص بـ SQLite داخل طبقة البنية التحتية (`base_repo.py`, `db_health_service.py`).
3. **تجريد الأنواع (Data Types):** استخدام أنواع موحدة (`DateTime`, `String`, `Integer`, `Text`, `BigInteger`).
4. **خطوات الانتقال المستقبلية:**
   - ضبط المتغير البيئي: `DATABASE_URL=postgresql://user:password@host:5432/plagiarism_db`.
   - استبدال دوال SQLite PRAGMA بإعدادات PostgreSQL Connection Pool.
   - نقل البيانات التاريخية عبر أداة تصدير موحدة إلى قاعدة البيانات المركزية.
