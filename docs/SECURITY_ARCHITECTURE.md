# دليل المعمارية الأمنية وعزل البنى التحتية (Security Architecture & Trust Boundaries)
## منظومة كاشف السرقات العلمية الأكاديمي للنصوص العربية — الإصدار v1.4.0-rc

---

## 1. حدود الثقة ونطاقات العزل (Trust Boundaries)

تم تصميم النظام وفق نموذج انعدام الثقة المحيطي (Zero-Trust Perimeter) الخاص بالبيئات الحكومية والجامعية المعزولة هوائياً (Air-Gapped LAN):

```
+-----------------------------------------------------------------------------------+
| [1] Client Layer ( المتصفح / المستخدم الأكاديمي )                                   |
|   - جلسات HttpOnly / SameSite=Lax / CSRF Tokens / إدخال البيانات المنضبط          |
+-----------------------------------------+-----------------------------------------+
                                          | (HTTP/JSON + CSRF Protection)
                                          v
+-----------------------------------------------------------------------------------+
| [2] Application Server Layer ( خوادم التطبيق وواجهات الإدارة )                     |
|   - عزل الجلسات / فرض صلاحيات RBAC / صمام الأمان Fail-Safe / إخفاء المسارات        |
+-------------------+---------------------+--------------------+--------------------+
                    |                     |                    |
       (DB Read/Write)         (CAS Storage API)         (DB Queue Claim)
                    v                     v                    v
+-------------------+ +-------------------+ +------------------+---------------------+
| [3] Database Tier | | [4] Shared CAS    | | [5] Background Worker Pool          |
|  - SQLite / PG    | |  - Sharded Storage| |  - مستقل تماماً (OS Processes)        |
|  - WAL Mode       | |  - Hash Immutab.  | |  - Claim Tokens / Leases           |
|  - App-Enforced   | |  - Path Isolation | |  - Fail-Closed Execution           |
+-------------------+ +-------------------+ +------------------+---------------------+
                    ^                     ^                    ^
                    |                     | (Periodic Drills)  |
+-------------------+---------------------+--------------------+--------------------+
| [6] Backup & Disaster Recovery Operator ( مسؤول النسخ الاحتياطي والتعافي )          |
|   - أقفال موزعة تمنع التضارب / فحص البصمات SHA-256 / عزل تام عن شبكة الإنترنت      |
+-----------------------------------------------------------------------------------+
```

## 2. أمان كلمات المرور وإدارة الجلسات (Authentication & Session Security)

1. **تشفير كلمات المرور:**
   - استخدام خوارزمية **`Bcrypt`** مع عامل تكلفة صلب `Cost = 12` وأملاح ديناميكية عشوائية لكل مستخدم.
   - ترحيل كلمات المرور القديمة المشفرة بـ `SHA-256` فقط وبشكل مشروط عند تسجيل الدخول الناجح للمستخدم.
   - حظر تام لتخزين أو طباعة كلمات المرور كنصوص واضحة في أي سجل أو ملف أو واجهة.
2. **أمان الجلسات وحمايتها:**
   - استخدام رموز `session_version` في قاعدة البيانات؛ حيث يؤدي تغيير كلمة المرور أو إعادة التعيين إلى إبطال فوري لكافة الجلسات السابقة للمستخدم.
   - حظر تسجيل دخول الحسابات المعطلة (`is_active = 0`) ومنع استخدام الجلسات للمستخدمين المحذوفين.
   - كووكيز الجلسة مؤمنة بالرايات: `HttpOnly=True`، `SameSite='Lax'`، مع مهلة خمول (`Idle Timeout`) ومهلة جلسة مطلقة (`Absolute Timeout`).

---

## 3. تأمين الإقلاع وتعيين المشرف الأول (First-Admin Bootstrap)

- إتاحة تهيئة المشرف الأول فقط لمرة واحدة عند كون النظام فارغاً (`users count = 0`).
- العملية محصنة ضد التزاحم (Race-Safe) وتُغلق بصورة نهائية ودائمة بمجرد إنشاء الحساب الأول.
- لا توجد أي بيانات اعتماد افتراضية مسبقة (No Default Passwords) في الشفرة المصدرية.

---

## 4. حماية واجهات البرمجة والمطفرات التدميرية (Destructive API Authorization)

- **التحقق من الصلاحيات (RBAC Pre-Check):**
  - كل نقطة نهاية تدميرية (`delete`, `cancel`, `retry`, `restore`, `backup`, `rebuild index`, `role change`) تفرض فحص صلاحيات المستخدم قبل تنفيذ أي عملية كتابة أو استهلاك موارد.
  - المستخدمون العاديون ومسؤولو إدخال البيانات ممنوعون تماماً من تنفيذ أي عمليات إدارية (إرجاع خطأ `403 Forbidden` فوري وتوثيق المحاولة في سجل التدقيق).
- **حماية CSRF وسلامة أفعال HTTP:**
  - كافة المسارات المحدثة للحالة تتطلب ترويسة/حقل CSRF صالح.
  - لا يُسمح نهائياً لأي طلب `GET` بإجراء أي تعديل أو حذف أو إتلاف للبيانات.

---

## 5. أمان رفع الملفات والفحص البنيوي (Upload Security)

> [!IMPORTANT]
> **إقرار أمني صريح:** الفحص البنيوي المطبق داخل النظام (`Structural Validation`) ليس بديلاً عن برامج مكافحة الفيروسات (`Antivirus Scanning`). النظام يتحقق من التوافق البنيوي، وهياكل ZIP/PDF، وقيود الحجم، والوقاية من القنابل الانضغاطية، ولكنه لا يقوم بالفحص الجنائي للبرمجيات الخبيثة.

- **الضوابط المطبقة:**
  - فحص الامتداد والترويسة السحرية (`Magic Bytes`) لملفات PDF و DOCX و TXT.
  - الحماية من هجمات اختراق المسارات (`Path Traversal`) بتجريد أسماء الملفات وتوليد معرفات تخزين معزولة.
  - الوقاية من قنابل الضغط (`Zip Bombs`) عبر قيود صارمة على عدد المدخلات، الحجم المفكوك، ونسبة الضغط.
  - تنظيف فوري لمساحة التجهيز المؤقتة (`Staging Cleanup`) عند فشل التحقق، والترقية الذرية (`Atomic Promotion`) للملفات السليمة فقط.

---

## 6. خصوصية مسارات الملفات (File Path Privacy)

- حظر ظهور المسارات المطلقة الداخلية للخادم في:
  - التقارير الأكاديمية المصدرة للباحثين والمراجعين.
  - استجابات واجهات البرمجة للمستخدمين العاديين.
  - صفحات الخطأ وسجلات التدقيق المرئية للعموم.
- الاعتماد حصرياً على المعرفات المنطقية الثابتة (`document_id`, `sha256`, `research_id`).

---

## 7. سلامة التخزين المتصل بالمحتوى (CAS Storage Integrity)

- تخزين الوثائق المرجعية والمرفوعة وفق تجزئة ثنائية المستوى مشتقة من بصمة المحتوى:
  `storage/documents/ab/cd/<sha256>/content.bin`
- **الكشف عن عدم التطابق (`HASH_MISMATCH`):**
  - فحص البصمة دورياً وعند القراءة.
  - عند اكتشاف أي تلاعب أو تلف في البصمة: تسجيل تنبيه فوري في سجل التدقيق، إيقاف استخدام الملف التالف، وحظر إصلاح الملف بصمت دون إشعار الإدارة.

---

## 8. موثوقية التقارير وسجلات التدقيق (Report & Audit Integrity)

1. **سلامة التقارير (Report Tamper-Evidence):**
   - توليد بصمة تدقيق `SHA-256` تسلسلية قانونية (`canonical JSON serialization`) لكل تقرير معتمد.
   - حفظ سلسلة المراجعات والتعديلات (`revision lineage`) مع ضمان عدم قابلية التقرير المعتمد للتعديل (`Finalized Report Immutability`).
   - المصطلح المعتمد نظامياً هو: **بصمة إثبات السلامة وعدم التلاعب (Tamper-Evidence Checksum)** وليس توقيعاً رقمياً قضائياً (Digital Signature).
2. **سجلات التدقيق غير القابلة للإلغاء (Append-Only Audit Trail):**
   - السجلات مدعومة بحماية من التعديل عبر واجهات التطبيق.
   - **خصوصية سجلات التدقيق:** حظر تام لتسجيل كلمات المرور، التوكنات، سلاسل DSN، أو النصوص الكاملة للأبحاث داخل تفاصيل أحداث التدقيق.

---

## 9. إدارة الأسرار والمتغيرات الحساسة (Secret Management)

- كافة المفاتيح الحساسة (مفتاح الجلسات `SECRET_KEY`، بيانات اعتماد قاعدة البيانات) تُدار عبر متغيرات البيئة أو ملفات الإعداد المحمية محلياً.
- لا توجد أي مفاتيح مشفرة أو أسرار مضمنة داخل الشيفرة البرمجية أو داخل بيانات الإصدار `release_manifest.json`.
