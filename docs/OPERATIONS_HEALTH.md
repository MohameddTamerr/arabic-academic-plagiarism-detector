# دليل المراقبة التشغيلية وصحة النظام (Institutional System Health & Operations)

## 1. نظرة عامة (Overview)

تم تصميم وتطوير طبقة **صحة النظام والمراقبة التشغيلية (Phase 11 - System Health & Operational Monitoring)** لتمكين الإداريين والمهندسين التقنيين المعتمدين في كلية الدراسات العليا من التحقق الفوري والمستمر من الحالة التشغيلية لمنظومة كشف الاستلال العلمي دون المساس بالخصوصية الأكاديمية ودون إرسال أي بيانات أو تتبع خارج المؤسسة (100% Offline).

## 2. مصفوفة شدة المكونات وتصنيفها (Component Severity Matrix)

يتم تصنيف كافة مكونات المنظومة في مصفوفة صريحة تحدد أثر تدهور المكون على صحة النظام الكلية:

| المكوّن (Component) | نوع المكوّن (Classification) | أثر التعطل (Critical) | أثر التدهور (Degraded) | أثر التعطيل العمدي (Disabled) |
| :--- | :--- | :--- | :--- | :--- |
| **قاعدة البيانات (database)** | `REQUIRED` | المنظومة حرجة `CRITICAL` فوراً | المنظومة تحتاج متابعة `DEGRADED` | غير قابل للتعطيل |
| **مساحة التخزين (storage)** | `REQUIRED` | المنظومة حرجة `CRITICAL` فوراً | المنظومة تحتاج متابعة `DEGRADED` | غير قابل للتعطيل |
| **النسخ الاحتياطي (backup)** | `POLICY_DEPENDENT` | المنظومة تحتاج متابعة `DEGRADED` | المنظومة تحتاج متابعة `DEGRADED` | حالة `not_configured` لا تخفض الصحة |
| **طابور مهام الفحص (scan_jobs)** | `POLICY_DEPENDENT` | المنظومة تحتاج متابعة `DEGRADED` | المنظومة تحتاج متابعة `DEGRADED` | لا يؤثر |
| **دفعات الفحص (batches)** | `POLICY_DEPENDENT` | المنظومة تحتاج متابعة `DEGRADED` | المنظومة تحتاج متابعة `DEGRADED` | لا يؤثر |
| **قاعدة المراجع (reference_corpus)**| `POLICY_DEPENDENT` | المنظومة تحتاج متابعة `DEGRADED` | المنظومة تحتاج متابعة `DEGRADED` | لا يؤثر |
| **إصدارات المنظومة (application)** | `POLICY_DEPENDENT` | المنظومة تحتاج متابعة `DEGRADED` | المنظومة تحتاج متابعة `DEGRADED` | لا يؤثر |
| **محرك التعرف الضوئي (ocr)** | `OPTIONAL` | المنظومة تحتاج متابعة `DEGRADED` (إن كان مفعلاً) | المنظومة تحتاج متابعة `DEGRADED` (إن كان مفعلاً) | **`DISABLED` (سليم ولا يخفض صحة النظام)** |
| **النموذج الدلالي (semantic_model)** | `OPTIONAL` | المنظومة تحتاج متابعة `DEGRADED` (إن كان مفعلاً) | المنظومة تحتاج متابعة `DEGRADED` (إن كان مفعلاً) | **`DISABLED` (سليم ولا يخفض صحة النظام)** |

## 3. مصفوفة الحالات التشغيلية المجمعة (Operational Health Statuses)

يتم احتساب الحالة العامة للمنظومة (`overall_status`) بصورة حتمية محددة وفق الأولويات التالية:

| الحالة بالإنجليزية | الحالة بالعربية | دلالة الحالة | إجراءات التدخل |
| :--- | :--- | :--- | :--- |
| `critical` | **حالة حرجة** | تعطل مكوّن أساسي مطلوب (`REQUIRED`) يمنع استمرار عمل المنظومة (مثل: انقطاع الاتصال بقاعدة البيانات، أو انخفاض مساحة القرص دون 5%). | تدخل فوري لمدير النظام لفحص الخادم أو إخلاء مساحة القرص. |
| `degraded` | **يحتاج متابعة** | المنظومة تعمل ولكن هناك وظيفة أو مكوّن يتطلب معالجة (مثل: مهام فحص عالقة، تجاوز عمر النسخة الاحتياطية 48 ساعة، عدم تفعيل نمط WAL، أو تفعيل OCR/النموذج الدلالي مع عدم توفر ملفاتهما محلياً). | فحص المكون المشار إليه في لوحة التحكم وتصحيح الإعداد أو استكمال الملفات الناقصة. |
| `healthy` | **سليم** | كافة المكونات المطلوبة تعمل بكفاءة تامة وضمن الحدود المعيارية. | لا يتطلب أي إجراء. |
| `disabled` | **غير مفعّل** | ميزة أو مكوّن اختياري تم تعطيله عمداً من الإعدادات (مثل تعطيل النموذج الدلالي). **لا يُعد خطأً أو تراجعاً في صحة المنظومة.** | استئناسي فقط. |
| `not_configured` | **لم يتم التحقق بعد** | مكوّن تشغيلي لم تُجرَ له عمليات بعد (مثل عدم إنشاء أي نسخة احتياطية في المنظومة الجديدة). | إنشاء أول نسخة احتياطية عند الجاهزية. |

## 4. دلالات النسخ الاحتياطي الرسمية (Authoritative Backup Semantics)

تعتمد المنظومة على فهرس النسخ الاحتياطي الرسمي (`BackupCatalog`) وتميز بدقة بين:
- **أحدث نسخة تم إنشاؤها (`latest_backup_id`):** أحدث سجل مسجل بالفهرس.
- **أحدث نسخة مكتملة (`latest_completed_backup_id`):** أحدث نسخة اكتملت معالجتها (`status = 'completed'`).
- **أحدث نسخة متحقق من سلامتها (`latest_validated_backup_id`):** أحدث نسخة اجتازت مطابقة SHA-256 وسلامة الأرشيف (`validation_status = 'valid'`).
- **أحدث نسخة فاشلة (`latest_failed_backup_id`):** أحدث محاولة واجهت خطأ أثناء الإنشاء.

### القواعد:
1. إذا فشلت المحاولة الأخيرة ولكن توجد نسخة سابقة صالحة: تظهر الحالة `degraded` مع توضيح الفشل وعرض بيانات النسخة الصالحة السابقة.
2. إذا كانت النسخة الأخيرة تالفة (`corrupted`): تظهر الحالة `degraded`.
3. إذا كانت النسخة الأخيرة مكتملة لكن لم يتم التحقق منها بعد (`pending`): تظهر الحالة `degraded` للتنبيه بوجوب إجراء التحقق.
4. إذا لم توجد أي نسخ مسجلة: تظهر الحالة `not_configured`.

## 5. العتبات والتهيئة التشغيلية (Operational Thresholds)

تم ضبط العتبات المعيارية في ملف `config.py`:

```python
DISK_WARNING_PERCENT = 15                 # تنبيه عند وصول المساحة الحرة إلى 15%
DISK_CRITICAL_PERCENT = 5                 # حالة حرجة عند وصول المساحة الحرة إلى 5%
STUCK_JOB_MINUTES = 30                    # مهلة اعتبار مهمة الفحص عالقة
BACKUP_MAX_AGE_HOURS = 48                 # مهلة التحذير من قدم النسخة الاحتياطية
HEALTH_AUTO_REFRESH_SECONDS = 30          # دورة التحديث التلقائي الهادئ في الواجهة
AUDIT_ALERT_SUPPRESSION_SECONDS = 300     # كبح تكرار التنبيهات المكررة في سجل التدقيق
```

## 6. كبح التنبيهات المكررة (State-Aware Alert Deduplication)

تطبق المنظومة آلة حالات ذكية لكبح التنبيهات المكررة:
- `healthy -> degraded / critical`: توثيق التحذير في السجل لأول مرة.
- `degraded -> degraded`: كبح التكرار وعدم ملء سجل التدقيق بالإنذارات المتكررة أثناء الفحص الدوري كل 30 ثانية.
- `degraded -> healthy`: توثيق التعافي والعودة للحالة الطبيعية.
- `healthy -> degraded`: توثيق حدث جديد عند تكرار المشكلة لاحقاً.

## 7. الخصوصية والأمان والخفة الفائقة (Privacy & Performance)

1. **خفة الفحص وعدم تحميل النماذج:**
   - فحص OCR يستخدم كاش بمهلة TTL (60 ثانية) ولا يطلق أوامر فرعية متكررة.
   - فحص النموذج الدلالي يتحقق فقط من وجود المجلد محلياً دون تحميل نموذج التضمين أو حجز ذاكرة GPU/CPU.
2. **الخصوصية التامة (Recursive Privacy):**
   - استجابة الـ JSON منقاة عودياً من أي مسارات مطلقة (`C:\Users\...`) أو نصوص أبحاث أو أسماء باحثين أو كلمات مرور.
3. **أداء الفحص القياسي (Benchmark Results):**
   - **الوسيط (Median):** `3.05 ms`
   - **مئين 95 (p95):** `3.93 ms`
   - **المتوسط (Mean):** `3.15 ms`
   - **أبطأ مكوّن:** `scan_jobs` بمتوسط `0.75 ms`.
