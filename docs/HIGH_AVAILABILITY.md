# وثيقة البنية عالية التوافر (High Availability & Scale Architecture)
## منظومة كاشف السرقات العلمية الأكاديمي للنصوص العربية — الإصدار v1.4.0-rc

---

## 1. المعمارية المستهدفة للبيئات الوزارية الموزعة (Target HA Architecture)

تم تصميم النظام ليعمل بكفاءة عالية على شبكة محلية وزارية معزولة عبر توزيع الأدوار على عقد مخصصة ومستقلة:

```
                            [ موازن الأحمال المحلي Load Balancer ]
                                        |
                 +----------------------+----------------------+
                 | (Stateless HTTP)                            | (Stateless HTTP)
                 v                                             v
    +-------------------------+                   +-------------------------+
    | خادم التطبيق 1 (App Svr 1) |                   | خادم التطبيق 2 (App Svr 2) |
    |  - جلسات مستقلة بالكامل   |                   |  - جلسات مستقلة بالكامل   |
    |  - معالجة واجهات الويب  |                   |  - معالجة واجهات الويب  |
    +------------+------------+                   +------------+------------+
                 |                                             |
                 +----------------------+----------------------+
                                        | (Database Pool & Job Submissions)
                                        v
                        +-------------------------------+
                        | خادم قاعدة البيانات الرئيسي    |
                        |   Primary DB (PostgreSQL / WAL)|
                        +---------------+---------------+
                                        | (Streaming Replication)
                                        v
                        +-------------------------------+
                        | خادم قاعدة البيانات الاحتياطي |
                        |   Standby DB (Read / Failover)|
                        +-------------------------------+
                                        ^
                                        | (Transactional Job Queue Claims)
                 +----------------------+----------------------+
                 |                                             |
                 v                                             v
    +-------------------------+                   +-------------------------+
    | مجمع العمال 1 (Workers Node 1)              | مجمع العمال 2 (Workers Node 2)              |
    |  - 4 Independent Processes                  |  - 4 Independent Processes                  |
    |  - كاشف الانتحال والاسترجاع                 |  - كاشف الانتحال والاسترجاع                 |
    +------------+------------+                   +------------+------------+
                 |                                             |
                 +----------------------+----------------------+
                                        | (Direct Storage I/O)
                                        v
    +-----------------------------------------------------------------------------------+
    | التخزين المشترك المتكرر المتصل بالمحتوى (Redundant Shared CAS Storage: RAID / NAS)  |
    |   - تجزئة مسارات الوثائق: `storage/documents/ab/cd/<sha256>/`                    |
    |   - فهارس استرجاع مرجعية مثبتة وغير قابلة للتعديل (Immutable Versioned Indexes)   |
    +-----------------------------------------------------------------------------------+
```

## 2. استقلالية وعدم اعتمادية خوادم التطبيق (Stateless Application Servers)

- **استقلالية الجلسات:** الجلسات لا تعتمد على الذاكرة المحلية للعملية (`No Process-Local Session Dependency`). يتم التحقق من صحة وصلاحية الجلسات وإصداراتها `session_version` عبر قاعدة البيانات.
- **توسع أفقي مرن:** يمكن تشغيل عدة خوادم ويب خلف موازن أحمال محلي دون الحاجة إلى تثبيت الجلسات برابط خاص (`Sticky Sessions`)، مما يوفر موثوقية عالية واستبدالاً شفافاً للخوادم عند الصيانة.

---

## 3. عالية توافر قاعدة البيانات والتخزين (Database & Storage HA)

1. **قاعدة البيانات (PostgreSQL Target HA):**
   - المعمارية جاهزة لدعم تقنية النسخ المتطابق التدفقي (`Streaming Replication`) مع وجود عقدة رئيسية للكتابة وعقدة احتياطية للتعافي السريع عند الأعطال (`Failover`).
   - في بيئة SQLite المحلية: يتم تفعيل نمط `WAL (Write-Ahead Logging)` مع معاملات ذرية وتأمين حماية القفل الموزع.
2. **التخزين المشترك (Shared Storage Redundancy):**
   - دعم التخزين الشبكي المشترك عالي الاعتمادية (RAID-10 / Enterprise NAS) مع عزل فيزيائي لكائنات CAS المرجعية.

---

## 4. استراتيجية فهارس الاسترجاع غير القابلة للانقسام (Retrieval Index HA Strategy)

- **تثبيت الإصدارات (Version Pinning):** كل فحص يرتبط بصورة حصرية ومغلقة بإصدار الفهرس المعتمد لحظة الإطلاق (`Corpus Snapshot`).
- **ترقية ذرية (Atomic Promotion):** يتم بناء الفهرس الجديد بالكامل في مسار مستقل، ولا يتم اعتماده كفهرس رسمي نشط إلا بعد اكتمال التحقق والتوقيع البرمجي له بنجاح، مما يمنع نهائياً قراءة أي حالة فهرس جزئية أو غير مكتملة.

---

## 5. تصنيف صحة الخدمات وتنبيهات الإدارة المحلية (Service Health & Alerting)

تقوم نقطة النهاية الصحية `/api/system/health` بتصنيف حالة المكونات بدقة دون الاعتماد على أي خدمات سحابية خارجية:

- **HEALTHY:** المكون يعمل بكفاءة تامة وضمن الحدود التشغيلية المعتمدة.
- **DEGRADED:** تحذير تشغيلي غير معطل للخدمة الأساسية (مثل: اقتراب مساحة القرص من 10GB، أو تأخر طفيف في النسخ الاحتياطي).
- **CRITICAL:** عطل جوهري يعطل عمليات الفحص (مثل: تعذر الاتصال بقاعدة البيانات، انخفاض مساحة القرص عن 5GB، أو توقف تام لكافة العمال).

> [!NOTE]
> المكونات الاختيارية غير المفعلة (مثل: OCR أو النموذج الدلالي) تُصنف بوضوح كـ `DISABLED` ولا تتسبب أبداً في رفع حالة النظام العامة بشكل خاطئ إلى `CRITICAL`.
